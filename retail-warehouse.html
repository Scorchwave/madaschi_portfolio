Retail Warehouse Analytics

From Python ETL to Power BI

End-to-end retail analytics project focused on transforming a large multi-table warehouse dataset into clean, validated and business-ready data for analysis and visualization.

Python Pandas Power BI ETL Data Modeling Business Intelligence

The Dataset

Retail Data Warehouse

The project uses a multi-table retail warehouse dataset containing information about customers, orders, products, categories, payments, shipments, returns, employees, suppliers, stores and promotions.

Large-Scale Data

The dataset contains more than one million rows distributed across 12 interconnected tables, providing a realistic environment for practicing data ingestion and relational data analysis.

Relational Structure

The different entities are connected through common identifiers, making the dataset suitable for building a relational analytical model rather than working with a single flat table.

Corporate Focus

The dataset covers both commercial and operational aspects of a retail business, creating opportunities to investigate sales, customers, products and supporting business processes.

Python ETL Pipeline

The first stage of the project was developed in Python using Pandas and pathlib. The objective was to create a reusable workflow capable of ingesting, cleaning, validating and exporting the warehouse data.

Data Ingestion

CSV files are automatically discovered from the raw data directory and loaded into Pandas DataFrames. The DataFrames are then organized inside a dictionary using the filename as the key.

Data Cleaning

The ETL process checks and removes missing values and duplicate records before the data is prepared for the analytical phase.

Data Transformation

The original abbreviated category identifiers were enriched with more readable business-oriented category names.

Data Validation

A reusable validation function checks the warehouse tables for missing values and duplicate records before the final export.

Python ETL Notebook

The complete Python workflow is available below, including data ingestion, inspection, cleaning, transformation, validation and export.

Data Model Preparation

Before moving to Power BI, Python was also used to identify potential relationships between the warehouse tables by comparing their column names and common identifiers.

Relationship Discovery

The program compares the columns of the different DataFrames and identifies tables that share common column names.

Potential Linking Keys

Each potential relationship records the common key together with the two tables in which it occurs.

Relationship Inventory

The detected relationships are stored in a structured DataFrame and exported as a CSV file to support the subsequent Power BI data-modeling phase.

Next Stage

The next stage of the project will use the cleaned data and identified relationships to build the analytical model and Power BI dashboard.
